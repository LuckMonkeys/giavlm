# 方案迭代模板

新方案可以复制下面的结构，保存为方法目录中的独立页面，例如 `dager/residual-v2.md`。版本号表示方法机制的变化；解释修订和超参数对比不必新增版本。

## 要点

- **本轮改变**：用一句话说明修改了哪一步。
- **采用状态**：候选、验证中、当前采用或已替代；有独立证据后再更新状态。
- **与上一版的关系**：链接上一个方案，说明替换了什么，哪些条件仍保持一致。

## 研究问题

描述上一方案的具体失败模式，以及新方法预期改善的指标。区分已观察到的现象与尚未验证的解释。

## 输入条件

| Item | Setting |
|---|---|
| Implementation | 对应攻击入口或研究代码 |
| Observation | 上传类型、样本数、参数范围 |
| Knowledge | 攻击者明确知道的图像、文本、长度等字段 |
| Model | 架构与必要的结构条件 |
| Private reference | 是否使用仅供诊断的私有参考；用在什么步骤 |
| Budget | 候选数量、搜索预算或优化预算 |

## 原理与流程

先介绍需要的概念，再给一个明确标为教学构造的小例子，最后对应到正式公式和实现。图中说明输入、输出、数据来源和打分方向；每个符号第一次出现时给出含义。

## 与上一版的区别

| Component | Previous | Proposed | Motivation |
|---|---|---|---|
| 修改的步骤 | 原处理方式 | 新处理方式 | 预期解决的具体问题 |

## 验证与结论

链接实际实验记录，说明哪些是开发结果、哪些经过冻结验证。记录覆盖、精度或序列恢复等对应指标，以及失败的对照；尚未运行时明确写“未验证”。

实验样本、结果产物和运行日志继续放在 Experiments 的记录中。方法页不维护另一套可能过期的实验明细表。

## 局限与下一步

写清信息损失、适用范围、数值和计算限制，以及哪些条件下预期会失效。下一步应能验证一个具体假设。

## 实现与修订记录

| Date | Revision | Description | Evidence |
|---|---|---|---|
| 整理日期 | 方案版本或解释修订 | 改了什么 | 代码位置、已有 commit 或实验记录 |

新增后更新方法目录页与 `mkdocs.yml` 导航。只有在实际切换方案时，才调整“当前采用”的标记；仅建立文档不改变默认攻击行为。
